# Banking Domain Knowledge Base — OpenFraud Investigator

This folder provides domain context for Claude Code. It is written for a synthetic, educational fraud-investigation application, with Indian banking context where useful.

## How to use this knowledge
- Read `BANKING_DOMAIN_OVERVIEW.md` first.
- Then read `BANKING_LIFECYCLE_AND_DATA.md`, `PAYMENTS_AND_TRANSACTION_SEMANTICS.md`, `FRAUD_TAXONOMY_AND_SIGNALS.md`, `FRAUD_INVESTIGATION_WORKFLOW.md`, `TERMINOLOGY_GLOSSARY.md`, `INDIA_REGULATORY_CONTEXT.md`, and `SYNTHETIC_CASEBOOK.md`.
- Follow `AI_DOMAIN_GUARDRAILS.md` for every implementation and AI response.
- Use `SOURCE_REGISTER.md` to verify time-sensitive regulatory statements.
- Treat this material as educational product context, not legal advice, bank policy, or a substitute for a bank's approved procedures.
- Distinguish regulatory requirements from industry practices, illustrative heuristics, and project-specific assumptions.

## Important boundaries
1. Use synthetic data only.
2. A detection alert is a signal for review, not proof of fraud.
3. A transaction record is not automatically proof of settlement, finality, account ownership, intent, or current balance.
4. Never claim a particular bank follows a workflow unless supported by a source.
5. RBI directions apply according to their scope and applicability; do not generalize one direction to every financial institution.
6. Do not use generated outputs to accuse a real person or make a real-world financial decision.
